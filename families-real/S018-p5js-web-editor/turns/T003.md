# T003 — Avisos de error anunciados como alerta

**Contexto.** Los avisos de error («Failed to save sketch.», «Network error», …) se muestran igual que los informativos, con `role="status"`, así que los lectores de pantalla no los anuncian con prioridad.

**Qué hay que hacer**

1. `showToast` acepta un tercer argumento opcional con la variante: `'info'` (por defecto) o `'error'`. Por ejemplo: `showToast('Toast.SketchFailedSave', 5500, 'error')`.
2. La variante del aviso visible se guarda en el estado del aviso (reducer `toast`) junto con el texto. Cualquier llamada sin variante (incluida la forma antigua `showToast(tiempo)`) es `'info'`.
3. El componente `Toast` muestra:
   - para `'error'`: `role="alert"`, `aria-live="assertive"` y las clases `toast toast--error`;
   - para `'info'`: como hasta ahora, `role="status"`, `aria-live="polite"` y la clase `toast`.
4. Un aviso informativo mostrado después de uno de error vuelve a ser informativo. Escape, el botón «X» y el cierre automático funcionan igual para ambas variantes.

**Notas**

- Los tests existentes del proyecto deben seguir pasando.
