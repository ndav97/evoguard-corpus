# T004 — Página y tamaño de página en la URL

**Contexto.** El orden de cada tabla ya se guarda en la URL, pero la página y el tamaño de página no: al recargar o compartir el enlace se vuelve a la primera página.

**Qué hay que hacer**

1. `useKuadrantDataViewPagination` acepta un tercer argumento opcional `urlKey?: string`.
2. Con `urlKey`:
   - la página y el tamaño iniciales se leen de los parámetros `<urlKey>.page` y `<urlKey>.perPage` de la URL; si faltan o no son enteros mayores que 0, se usan 1 y el tamaño inicial;
   - cada vez que cambian la página o el tamaño (también cuando la página se ajusta porque hay menos elementos), se escriben esos dos parámetros en la URL con `history.replaceState`, conservando la ruta, los demás parámetros y el *hash*.
3. Cada tabla usa su propia clave, así que varias tablas no se pisan.
4. Sin `urlKey`, el *hook* no lee ni escribe la URL.

**Notas**

- El comportamiento actual de la paginación (volver a la primera página al cambiar el tamaño y ajustar una página fuera de rango) se mantiene.
- Los tests existentes del proyecto deben seguir pasando.
