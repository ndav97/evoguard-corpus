# T003 — Avisos y advertencias

**Contexto.** Algunas comprobaciones de los campos de Pods no son errores, sino advertencias (por ejemplo, «el valor es muy largo para mostrarse en listas») o información. `ValidationMessages` (`ui/js/dfv/src/components/validation-messages.js`) solo acepta textos y los muestra todos como errores.

**Qué hay que hacer**

1. Cada elemento de `messages` puede ser un texto (un error, como hasta ahora) o un objeto `{ message, status }`, con `status` igual a `error`, `warning` o `info`. Si el `status` falta o es otro valor, se trata como `error`. Los elementos que no son ni texto ni un objeto con `message` de tipo texto se descartan. Actualiza `propTypes` para aceptar las dos formas sin avisos.
2. Cada aviso (`Notice`) usa el `status` de su mensaje.
3. Los mensajes se ordenan: primero los errores, luego las advertencias y por último la información, conservando el orden original dentro de cada grupo.
4. Dos mensajes se consideran repetidos si tienen el mismo texto (sin los espacios de los lados) y el mismo `status`. El mismo texto con distinto `status` se muestra dos veces.
5. `maxVisible` se aplica después de ordenar.
6. Lo de los turnos anteriores se mantiene.

**Notas**

- Los tests existentes del proyecto deben seguir pasando, y los tests no deben producir avisos en la consola.
