# T003 — Borrado asíncrono con espera y reintento

**Contexto.** Hoy el diálogo llama a `deleteFn` y se cierra en el acto, aunque el borrado en el servidor tarde o falle.

**Qué hay que hacer**

1. `deleteFn` puede devolver una promesa. El tipo de la prop pasa a ser `() => void | Promise<unknown>`.
2. Si devuelve una promesa:
   - mientras está pendiente, el botón de borrar muestra `t('deleting')` y está deshabilitado, y el diálogo no se cierra;
   - si se resuelve, se llama a `closeFn`;
   - si se rechaza, el diálogo sigue abierto, muestra un elemento con rol `alert` con el texto `t('deleteFailed')` y el botón vuelve a mostrar `t('delete')` habilitado para reintentar.
3. Si `deleteFn` no devuelve una promesa, el diálogo se cierra en el acto, como ahora.
4. Al cerrar y volver a abrir el diálogo, desaparecen el aviso de error y el estado de espera.
5. Añade a `src/locales/en/translation.json` las claves `"deleting"` y `"deleteFailed"` con su texto en inglés (por ejemplo, `"Deleting…"` y `"Could not delete. Please try again."`).

**Restricciones**

- La confirmación escribiendo un texto y el botón de cierre accesible siguen funcionando igual.
- Los tests existentes del proyecto deben seguir pasando.
