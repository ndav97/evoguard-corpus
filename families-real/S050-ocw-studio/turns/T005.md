# T005 — Confirmar antes de cambiar

**Contexto.** Algunos campos booleanos tienen consecuencias fuertes (por ejemplo, ocultar una página publicada). Queremos que el formulario pueda pedir confirmación, incluso asíncrona (un diálogo), antes de aceptar el cambio en `BooleanField` (`static/js/components/widgets/BooleanField.tsx`).

**Qué hay que hacer**

1. Añade a `BooleanField` la prop opcional `confirmChange(next)`, que recibe el valor que se quiere elegir (`true`, `false` o `null`) y devuelve un booleano o una promesa de booleano.
2. Al elegir una opción con `confirmChange`:
   - se llama a `confirmChange` con el nuevo valor;
   - solo si devuelve `true`, o la promesa se resuelve con `true`, se llama a `onChange` como siempre;
   - si devuelve `false`, la promesa se resuelve con otra cosa o se rechaza, no se llama a `onChange` y no se produce ningún error sin capturar.
3. Mientras se espera una promesa, todas las opciones están desactivadas, el contenedor del campo (el `<div>` o el `<fieldset>`) lleva `aria-busy="true"` y no se aceptan otros cambios. Al terminar vuelven a estar como antes y `aria-busy` desaparece.
4. Sin `confirmChange`, `onChange` se llama de inmediato, como hasta ahora. Con `disabled` no se llama a `confirmChange`.
5. Lo de los turnos anteriores se mantiene.

**Notas**

- Los tests existentes del proyecto deben seguir pasando.
