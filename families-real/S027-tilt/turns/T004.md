# T004 — Alternativas separadas por comas en el filtro por nombre

**Contexto.** `matchesResourceName(resourceName, filter)` (`src/ResourceNameFilter.tsx`) exige que el nombre contenga todas las palabras del filtro (separadas por espacios) y que no contenga ninguna palabra de exclusión (las que empiezan por `-`). Para ver, por ejemplo, los recursos de la API y los del frontend a la vez no hay forma de expresarlo.

**Qué hay que hacer**

1. Dentro de una palabra del filtro, las comas separan **alternativas**: la palabra se cumple si el nombre contiene **alguna** de ellas. Con `api,web`, pasan `api-server` y `web-frontend`, pero no `db`.
2. En una exclusión, las alternativas se excluyen todas: con `-api,web`, quedan fuera los nombres que contengan `api` o `web`.
3. Las palabras siguen combinándose entre sí: con `prod api,web`, pasa `prod-web` pero no `dev-web` ni `prod-db`.
4. Las alternativas vacías se ignoran (`api,` equivale a `api`), y una palabra sin ninguna alternativa (`,` o `-,`) se ignora por completo.
5. La búsqueda sigue sin distinguir mayúsculas.

**Notas**

- Un `-` suelto se sigue ignorando y un filtro vacío sigue dejando pasar todo.
- Los tests existentes del proyecto deben seguir pasando.
