# T004 — El paso debe encajar en el rango

**Contexto.** Con un rango de 0 a 10 y un paso de 3, el último valor permitido no coincide con el máximo, y el formulario resultante es confuso.

**Qué hay que hacer**

1. Cuando el mínimo, el máximo y el paso tienen valor, son válidos y el rango no está invertido, comprueba que `(máximo − mínimo) / paso` sea un número entero (con una tolerancia pequeña, para que `0` a `1` con paso `0.1` se acepte).
2. Si no lo es, marca como inválido el campo del paso con el texto `The range must be a multiple of the step` (`t('stepDoesNotFitRange', …)`). El mínimo y el máximo no se marcan por ello.
3. Si el paso no es válido, se muestra su aviso de siempre (`Step must be a number greater than 0`) y no este.
4. Si falta alguno de los tres valores, o el rango está invertido, no se hace esta comprobación.
5. Las opciones guardadas no cambian: la comprobación solo avisa.

**Notas**

- Los tests existentes del proyecto deben seguir pasando.
