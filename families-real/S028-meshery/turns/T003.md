# T003 — Elegir la API version más reciente comparando números

**Contexto.** La función por defecto de `utils/versionSort.ts`, `getMostRecentVersion(versionList)`, elige la API version de Kubernetes que se debe usar para un componente: prefiere las estables (`v1`) a las beta y las beta a las alfa. Pero ordena como texto (`v1beta2` sale por delante de `v1beta10`), solo reconoce como estables `v1`…`v9` (`v10` no) y no entiende las versiones con grupo (`apps/v1`).

**Qué hay que hacer**

1. Reconoce estos formatos en cada entrada de la lista:
   - estable: `v<N>` (`v1`, `v10`);
   - beta: `v<N>beta<M>` (`v1beta2`);
   - alfa: `v<N>alpha<M>` (`v2alpha1`).
2. Si la entrada lleva grupo (`apps/v1`, `networking.k8s.io/v1beta1`), se clasifica por lo que va tras la última `/`, pero se devuelve la entrada completa, tal cual.
3. Prioridad: estable > beta > alfa, sea cual sea el número. Dentro del mismo nivel gana la `N` mayor y, con la misma `N`, la `M` mayor, comparando como números (`v1beta10` > `v1beta2`, `v10` > `v9`).
4. Si ninguna entrada se reconoce, se devuelve la primera de la lista, como ahora; con la lista vacía o sin lista, `undefined`.

**Notas**

- `versionSortComparatorFn` y las demás funciones del archivo no cambian.
- Los tests existentes del proyecto deben seguir pasando.
