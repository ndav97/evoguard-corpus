# T003 — Normalizar el repositorio

**Contexto.** El repositorio de GitHub vinculado a un snap a veces llega como `owner/repo`, pero otras veces como URL (`https://github.com/owner/repo`), con `.git` al final o como remoto SSH (`git@github.com:owner/repo.git`). Con esas formas, `createGitHubCommitUrl` (`static/js/publisher/utils/formatGitCommit.tsx`) devuelve `null` y no se muestra el enlace.

**Qué hay que hacer**

1. Añade y exporta `normalizeGitHubRepository(githubRepository)`, que devuelve `owner/repo` o `null`. Acepta, ignorando los espacios de los lados:
   - `owner/repo`;
   - la misma referencia precedida de `github.com/`, `www.github.com/`, `http://` o `https://` delante de cualquiera de las dos anteriores (sin distinguir mayúsculas en el dominio);
   - `git@github.com:owner/repo`;
   - en todos los casos, con un `.git` y/o una `/` opcionales al final.
2. `owner` y `repo` solo pueden contener letras, dígitos, `_`, `.` y `-`, y no pueden ser `.` ni `..`. Cualquier otra forma (rutas más largas como `owner/repo/tree/main`, otros dominios, texto vacío, `null`…) devuelve `null`.
3. `createGitHubCommitUrl` usa el repositorio normalizado para construir la URL (siempre `https://github.com/owner/repo/commit/<id>`). En consecuencia, `GitCommitLink` muestra el enlace con cualquiera de esas formas.
4. Lo de los turnos anteriores se mantiene.
